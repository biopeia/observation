## 1. Governing distinctions

These roles and source dimensions must not be conflated:

- **Subject:** entity or process the datum is about.
- **Semantic authority:** domain entitled to define what the datum means. This is not necessarily the emitting component.
- **Producer:** component that extracts, computes, projects, or serializes the representation seen by a consumer.
- **Measurement source:** apparatus or source state from which an observed value is acquired. It supplies a factual sample without thereby becoming a semantic authority domain.
- **Observer/consumer:** component that receives the representation and may derive a separately attributed result.

The following are separate questions, not synonyms:

```text
semantic authority != measurement source != producer != transport host != consumer
```

This is a proposed cross-domain architectural invariant, not yet an approved permanent invariant. The authority domains considered by this matrix are `Symbiont`, `Embodiment`, `Modality`, `Environment`, and `Lab`. `Body` is treated as a subject/entity, not an authority domain: physical body facts may be Embodiment-authoritative, while Symbiont-owned learned representations *about* that body remain Symbiont facts. Likewise, `World`/environment instance is a subject; `Environment` is the candidate authority. `UI` may own presentation representations, never semantic authority over source facts.

A domain may derive a value internally and retain authority over it when that derivation is part of its explicit domain model; cross-domain inputs alone do not transfer authority to Lab. An observer may transform a value without inheriting authority over its source meaning. If a transformation adds a new classification, estimate, comparison, or aggregation, that output is a distinct observer-derived datum and must retain lineage to all inputs. `derived_from` is therefore a graph (zero or more source observations), not a single source label.

**Semantic authority is not causal responsibility.** The domain defining what an observation means need not be the actor that caused a state transition, measured an input, or computed an intermediate value. Trace both each datum's role in a causal chain and the actor responsible for each transformation/state transition; neither axis implies semantic ownership or licenses observer-to-organism feedback.

### Classification vocabulary for this inventory

Do not use `reported` as a catch-all. Use these independent axes when tracing a datum:

| Axis | Candidate values / meaning |
| --- | --- |
| `semantic_authority` | One of the authority domains above; provisional until domain-owner review. |
| `epistemic_nature` | `source_owned_state`, `source_assertion` (only where the source has an explicit assertion/observation contract), `apparatus_measurement`, `domain_derived_state`, `observer_derived`, orchestration/transport metadata, ground truth, or unresolved. Cross-domain input lineage is recorded separately under `derivation_scope`; derivation does not by itself determine authority. |
| `derivation_scope` | `none`, `intra_domain`, `cross_domain`, or unresolved. Independent of `semantic_authority`: cross-domain inputs may feed a derivation owned by one domain. |
| `causal_role` | Role in a causal chain, independent of authority: `state`, `measurement`, `input`, `command`, `consequence`, `accounting_adjustment`, or unresolved. A tracing aid, not a proposed wire field. |
| `causal_responsibility` | Actor/component that causes a state transition or performs a derivation; distinct from semantic authority and causal role. Trace as provenance, not a proposed wire field. |
| `acquisition_method` | Concrete mechanism such as runtime state export, simulator sampled state, manifest/launch metadata, observer computation, or transport counter. This says how obtained, not what it means. |
| `measurement_source` | Apparatus/source supplying the factual value (for example MuJoCo model/data); distinct from semantic authority and from the component that serializes it. |
| `transformation_fidelity` | `identity`, `normalization`, `lossy`, `derived`, or a documented combination. Conversions/casts and aliasing must be explicit; truncation, clamping, aggregation, thresholding, and reduction are lossy/derived. |
| `derived_from` | Graph of input observations plus named/versioned transformation for every newly meaningful derived output. |

Identity tracing also distinguishes **issuer** (domain that minted an identifier) from **asserter** (runtime, Lab launch manifest, adapter, or other source that supplies its value to this observation). If runtime identity conflicts with launch metadata, the observation layer must surface a conflict; it must not silently pick a precedence and make the values indistinguishable.

Temporal references should map to a typed conceptual `ClockRef`, rather than a context-dependent bare `tick`: `organism_cycle`, `embodiment_cycle`, `simulation_step`, `simulation_time`, `observation_sequence`, `world_revision`, and `projection_revision` are candidates. Existing names remain evidence of implementation only; this list is not a wire schema.

### Evidence labels used here

- **Confirmed (code):** source path and behavior are visible in the current checkout; this does not prove the owner has approved the semantic interpretation.
- **Probable:** the source domain is suggested by types/contracts and data flow, but owner authority needs review.
- **Pending:** origin, semantics, consumer contract, or domain owner cannot be safely decided from the inspected code alone.
- `current contract`: an existing payload shape with consumers, not a claim that it is canonical across domains.
- `candidate public`: a datum that appears useful across a boundary; publication still requires owner approval and data minimization.

## 2. Current production path (confirmed code)

For a managed Physics3D session, the inspected path is:

```text
runtime snapshot + physical_state
  -> lab.observation.physics3d.Physics3DObservationBridge
       -> runtime_tick_events()             [body / cognition / vitals]
       -> mind_snapshot_from_rich_state()   [Mind view projection]
       -> project_world_scene()             [Body-in-World observer projection]
       -> ObservedFrame                     [coherent presentation frame]
  -> lab.observation.bus.ObservationBus
  -> lab.server.api + lab.server.sse (/api/organism, replay/history)
  -> workbench Mind / Body consumers
```

This establishes that the Lab currently produces meaningful projections. It does not establish that Lab owns the source facts embedded in those projections, nor that all projected fields are appropriate to publish.

### Replacement posture (proposed target constraint; not a description of current state)

The target is a **complete replacement** of the present operational telemetry/observation arrangement, not a compatible extension of it. The current `/api/organism` payloads and related Lab-owned stream contracts (`body`/`cognition`/`vitals`, Mind snapshots, `ObservedFrame`, current replay/cursor behavior, and direct frontend assumptions) are inventory evidence only; they are not compatibility contracts to preserve.

The eventual cutover is intended to remove the old path and its duplicate projections/consumers as the new observation contract takes ownership. Do not design compatibility routes, adapters, aliases, dual publication, compatibility windows, or incremental coexistence as requirements. Existing consumers may be rewritten against the approved target contract; the replacement need not retain field names, event boundaries, endpoint paths, event IDs, or payload semantics. No legacy mode should silently remain as a second truth source.

This does **not** prohibit controlled differential testing during replacement. Tests may feed the same captured source state to the old projection and a candidate implementation, then classify removals, additions, authority changes, information loss, and intentional semantic changes. They must not require payload equality or promote old output to an oracle. This is validation evidence only: no production dual publication, compatibility adapter, or second live source of truth.

This full-replacement constraint applies to the **operational observation/telemetry plane**. It does not claim to replace durable scientific evidence, frozen study protocols, or Physics3D research artifacts; those remain separate governed evidence systems and cannot be treated as equivalent to the operational stream. Implementation sequencing and authorization remain undecided; this document does not authorize code changes.

### 9.3 Affordances: source-owned derivation, not a raw world opportunity

#### Bounded revolute-joint position/velocity unit trace — 2026-10-07 (closed)

Current generated actuated joints are emitted as `type="revolute"` by `ArticulatedBody`/the Physics3D body generator. The generated URDF does not add a distinct public physical-observation unit declaration; `JointSpec` itself also has no unit-typed fields. **Closed finding:** for the current Physics3D generated revolute joints, the source-to-export path is consistent with position in `rad` and velocity in `rad/s`, with no post-sampling conversion. This is a current backend behavior trace, not an Embodiment-owned backend-neutral contract. It does not establish axis sign/frame semantics, a versioned public unit declaration, or units for other joint types/backends. The inspected tests compare state against the same `JointSpec` limits or assert movement; they do not independently verify a public unit contract.

#### Bounded Physics3D physical-state sampling cadence trace — 2026-10-07 (closed)

`Physics3DRuntime.step()` captures a pre-step physical state, advances the organism once, then performs `physics_substeps_per_tick` simulator steps while holding the actuation. Separately, within the substep loop, presentation pose frames are sampled when a phase accumulator reaches `physics_hz` relative to `presentation_hz`; each carries `tick`, within-tick `substep_index`, cumulative `physics_step`, derived `simulation_time_s`, `tick_simulation_span_s` and `sampling_hz`. Those frames are capped to the latest eight. Thus current tick-end physical telemetry and render-cadence frames are distinct acquisition paths and rates; the exported physical-state object itself has no embedded sample clock. MuJoCo's free-joint state documentation explains the underlying `qvel` components, but does not establish the Lab runtime's public clock semantics.

**Closed finding:** current collection points and cadence split are identified. This is not a public temporal contract: the tick-end physical state is associated out-of-band with the current organism tick, while presentation frames expose several apparatus counters/times. Their cross-clock relationship, sampling completeness, and whether base velocity belongs in presentation frames or only tick-end state remain unresolved for target design.

#### Physiology ownership and re-embodiment trace (code behavior; semantic ownership unresolved)

The current Physics3D replacement path gives a concrete answer about **implemented lifecycle behavior**, but not final domain ownership. When `lab/src/lab/physics3d/runtime.py` detects a fresh physical Body (`physical_state is None`), it builds a fresh organism checkpoint and passes the prior checkpoint through `symbiont/src/symbiont/core/embodiment/transition.py::prepare_fresh_embodiment_checkpoint()`. That function explicitly replaces the prior physiology bundle with the fresh template values. It preserves longitudinal Symbiont cognition/genome and embodiment archive/knowledge through separate paths, while resetting active physiology and Body-bound execution state.

Checkpoint placement adds a separate, unresolved architectural dimension. `OrganismRuntime.checkpoint()` includes `metabolism`, `living_body`, `homeostasis`, and `physiology` in the organism checkpoint bundle (`symbiont/src/symbiont/core/orchestration/runtime.py`). Thus current active physiology is serialized with the portable organism checkpoint even though the fresh-embodiment path resets selected physiological values from a new-Body template. This is evidence about artifact placement and lifecycle behavior, not proof that all physiology is semantically organism-owned or portable.

The two checkpoint artifacts are written separately: `lab/src/lab/physics3d/engine.py::_save_checkpoint()` captures the organism bundle and physical checkpoint, then persists the organism bundle and Body file through separate writers. Restore checks the saved organism tick against the physical checkpoint's `symbiont_ticks`; missing or mismatched tick identity fails normal resume, while an explicit `--fresh-body` path selects the distinct re-embodiment flow. The unit test `lab/tests/unit/lab/physics3d/test_shutdown.py::test_resume_requires_matching_body_or_explicit_fresh_body` exercises rejection of missing/mismatched Body state and the explicit fresh-Body alternative. This is a fail-closed cross-artifact tick-alignment check, not an atomic transaction over both files and not proof that each physiological value is linked to the correct Body identity, semantic owner, or clock. Do not characterize current restore as lacking all coherence checks; the demonstrated guarantee is narrower than those unresolved questions.

The replacement transform archives the prior Body/episode context before replacing the active physiology bundle. There are two distinct historical summaries, which should not be conflated. `archive_episode_checkpoint()` adds a bounded `EmbodimentEpisodeSummary` to `embodiment_archive`; for physiology it retains `final_body_age_ticks` and `body_vital_state`, not the full `living_body` checkpoint. Neither summary preserves raw reserve/capacity, temperature, growth progress, per-structure states, or the full metabolic-channel/accounting maps. The active `living_body`, `metabolism`, `homeostasis` and `physiology` bundle is replaced with the fresh template. The current embodiment lifecycle/history projection is capped at 8 entries (`transition.py::_MAX_EMBODIMENT_HISTORY`); the separate epoch summaries are capped at 16 (`longitudinal.py::_MAX_EPOCH_SUMMARIES`). Thus current behavior is fresh reinitialization plus **selected, lossy, bounded longitudinal summaries**, not preservation of full physiology as history. The source model itself makes a useful but non-normative distinction: `LivingBodyState` is documented as the persistent physiological state of **one Body**, and documents `age_ticks`/`death_tick` as Body-local biological time, distinct from the persistent Symbiont historical tick. These declarations, together with the continuity register's same-Body-preserve/fresh-Body-replace policy and `prepare_fresh_embodiment_checkpoint()` comment (“A fresh Body owns fresh physiology”), provide strong evidence for the current model's intended Body-scoped boundary. They still do not settle the public semantic authority for each quantity or whether Symbiont should expose a separate internal estimate/regulatory state. The code supports these narrower statements: current physiology is attached to one Body; re-embodiment resets/replaces its active instance; Symbiont identity/history can continue independently.

`BodyStructureState` requires additional caution. Its own module documentation calls `structure_id` opaque (currently an actuator slot ID), and describes `functional_capacity` and `repair_progress` as stored/checkpointed scaffolding. The source trace refines that description: runtime construction populates entries from actuator constitution slots; integrity is read to compute aggregate integrity; `apply_structural_delta()` updates integrity and increments wear/damage on negative deltas or repair progress on positive deltas. The re-embodiment fate `RESET_ON_REEMBODIMENT` describes replacement of the active state map by fresh-template state, not an owner-approved lifecycle rule.

The case also shows why **semantic authority and causal responsibility must stay separate**. For example, Physics3D derives a mechanical-work estimate from commanded actuator torque, simulated angular velocity and integration duration; the Lab-side runtime applies a configurable work-to-metabolic-cost conversion and queues the result; Symbiont later accounts for that input against shared reserve and updates modeled physiology. `mechanical_work_joules` is therefore not an independently sensed work measurement merely because its name contains a physical unit. The conversion is a cross-domain causal transformation/input, not automatically Lab-owned physiology; the downstream state change is not itself an apparatus measurement. Preserve the chain as distinct causal nodes and lineage rather than assigning the whole chain one owner.

The inspected V41 `effective_configuration` does not include `mechanical_work_cost_per_joule`. This has two separate implications and must not be collapsed into one remediation claim:

- **Operational observation:** the currently inspected outputs do not expose enough conversion-configuration provenance to reconstruct the relationship between the work estimate and the queued cost from those outputs alone.
- **Scientific evidence:** V41 may not preserve an effective input needed to reproduce that derived quantity. This is a separate evidence/protocol review question; it is not automatically an Observation Plane requirement, and this assessment does not conclude that the scientific artifact is invalid.

For future lineage analysis, record derivation-configuration provenance alongside source inputs, transformation identity/version, the application boundary and resulting state where those facts are available. This is a tracing requirement, not a prescription that every item become a field in an operational record. It also remains unresolved whether `metabolic_work_cost` is a legitimate public operational observation at all: v1 could expose the work estimate and later physiology state without publishing the intermediate causal scalar, provided supported consumers do not require it and the causal relationship remains represented in an appropriate diagnostic or scientific record.

The conversion's semantic authority remains unresolved. Current execution in the Lab-side Physics3D runtime establishes the producer/location, not who should define the meaning of the coefficient or output. Plausible owners include Embodiment (Body-specific cost semantics), Symbiont (metabolic response semantics), or an explicitly configured experimental relationship; evidence and owner review are required before assigning authority.

#### Lab prediction-error classification and consumer trace (legacy projection)

`lab/src/lab/observation/projection.py::_prediction_class()` derives a categorical value from the absolute value of `float(error)`: `zero` for `<=1e-12`, `trace` for `<0.01`, `low` for `<0.05`, `medium` for `<0.15`, `high` for `<0.4`, and `extreme` otherwise. These thresholds are inline constants; no configuration or classifier revision accompanies the output. The same projection separately retains the signed numeric `error` in `predictionErrorValues`, while the categorical map is recorded as `observer_analysis.predictionErrors` with provenance text identifying an observer classification. It is a lossy second datum, not a replacement for the signed residual.

The numeric conversion is permissive rather than a finite-number validator: Python booleans are accepted by `float()`, and parsed NaN/positive or negative infinity reach the final `extreme` branch. Values that cannot be parsed are omitted. This behavior is confirmed by direct inspection; no focused boundary tests for these cases were found in the searched tests. This is a legacy projection risk, not a reason to encode its edge behavior in a future contract.

The derived category has several observer consumers with further transformations. Mind's cognitive controller uses the category map to enrich its graph; Atlas associates the separately preserved numeric value with predictor-node metadata. The observer-map model maps categories to fixed scores (`zero=0`, `trace=0.08`, `low=0.25`, `medium=0.55`, `high=0.8`, `extreme=1`), averages them, and combines that mean with a safety-failure penalty to derive a display `predictiveTension`. Thus the visualization metric is a Lab/UI-derived aggregate of already Lab-classified values plus a separate safety status, not an organism state or direct prediction-error measurement. Mind history fingerprints the categorical map along with topology/revision and captures a history snapshot when the fingerprint changes or its tick gap is reached; that is a presentation/history sampling policy, not complete event history.

The Development-history path also reads `observerAnalysis.predictionErrors` from serialized telemetry snapshots and uses it in snapshot fingerprints/derived history selection. This establishes a consumer path, not durable scientific-artifact status or full-fidelity retention. These uses make the candidate Lab-derived class useful as an operational projection, but its current thresholding, edge-value handling, downstream score mapping and history capture are unversioned semantics. Any future inclusion must either define and version those derivations explicitly or omit them; do not infer that the old category names or weighted display score are canonical.

#### Bounded actuator-command to Physics3D application trace

The organism-owned `ActionDomain` issues a `MotorCommand` only under an active `ActionCommitment`; the command carries that commitment, controller, competence (if any), opaque actuator channels, the actuator-surface fingerprint, the organism tick and embodiment identity. `execute_command()` checks that the command belongs to the active commitment and a known trace, then `ActuatorSystem` verifies the surface fingerprint and validates each channel/value against that surface before recording `Actuation(requested, delivered)`. When the canonical Physics3D runtime returns from `organism.tick()`, `_apply_runtime_actuation()` maps opaque actuator IDs to apparatus effector IDs by ordinal and applies the delivered values. `ArticulatedBody.apply_effectors()` resolves paired positive/negative ports into joint torque `(positive - negative) * max_motor_torque`; `prepare_physics_substep()` adds passive end-range resistance before MuJoCo integrates. The next physical export therefore samples simulated state after actuation, not merely the command itself.

The organism separately stages requested/delivered activation values as proprioceptive channels for a later perception tick. Those channels echo the command boundary; they are not a measurement of resulting joint movement. The runtime's `PhysicsReadingProvider`/sensory path is distinct and is the candidate route for physical readings into percepts. This bounded trace closes the command-to-apparatus delivery segment only. It does not prove command efficacy, map each resulting physical measurement back to the command as causal evidence, or establish a public identity/clock/unit contract. Evidence includes `ActionDomain.issue_command()`/`execute_command()`, `ActuatorSystem.execute_command()`, Physics3D `_apply_runtime_actuation()` and `step()`, `actuator_to_effector_map()`, `ArticulatedBody.apply_effectors()`/`prepare_physics_substep()`, plus `test_physics3d_applies_all_concurrent_actuations_in_one_tick` and the apparatus dynamics tests. The intentional-execution integration test exercises intent → commitment → command → attempt and a later organism-model effect match; that effect match is not independent apparatus ground truth.

## 11. Decisions established for this design

These decisions establish the conceptual boundary for this design; they do not assign authority to individual fields, approve a public field inventory, or authorize implementation. Permanent constitutional adoption remains subject to the repository's ADR and explicit-owner process.

1. **Role separation is an architectural invariant for the observation plane:** `subject`, `semantic_authority`, `measurement_source`, `producer`, `transport_host`, and `observer/consumer` answer distinct questions. In particular:

   ```text
   semantic_authority != measurement_source != producer != transport_host != consumer
   ```

   This ontology decision does not approve any particular datum-to-domain assignment.
2. **Classification dimensions remain independent.** The conceptual model includes `semantic_authority`, `epistemic_nature`, identity/provenance, `ClockRef`, and lineage. `derivation_scope`, `causal_role`, `causal_responsibility`, `acquisition_method`, `measurement_source`, and `transformation_fidelity` are tracing dimensions that inform the contract; they need not all become wire fields. Derivation, including cross-domain derivation, does not itself determine authority.
3. **The observation-plane authority vocabulary is scoped to five domains:** `Symbiont`, `Embodiment`, `Modality`, `Environment`, and `Lab`. `Organism`, `Body`, `EmbodimentEpisode`, `EnvironmentInstance`/`World`, `Signal`, `Resource`, and `Run` are candidate subject/entity kinds, not authority domains. This is an observation-design ontology, not a silent rewrite of the Constitution's repository/domain topology.
4. **Lab authority is bounded to Lab-created semantics.** Lab may own its observer classifications, comparisons, aggregates, cross-domain joins, diagnostics, and analytical/presentation metrics. It does not thereby gain authority to redefine an input source fact. A derived value must be separately identified and carry lineage to its inputs; UI can own presentation representations, not source-fact semantics.
5. **`organismFacts` / `observerDerived` is legacy evidence only, not the canonical provenance model for the replacement.** Its binary classification cannot represent the authority domains, epistemic natures, or derivation lineage required here. Provenance may be shared at record/subtree level only when all contained values are homogeneous; heterogeneous subtrees must split or carry nested provenance.
6. **A canonical observation unit may not hide mixed semantic authority or epistemic nature under an aggregate family name.** Transport batching may group distinct observation records, but the batch does not grant its members common semantics or authority. This rejects `body`/`cognition`/`vitals` as canonical semantic taxonomies without requiring one event per primitive value.
7. **Publication policy has three distinct classes:**

   - **Public operational observation:** publish only when semantics and authority are resolved, identity and time are sufficient, applicable units/frames are defined, representation is bounded, a legitimate operational consumer exists, the domain owner permits exposure, and publication creates no feedback dependency.
   - **Private/debug observation:** keep outside the public contract when a value is unstable, implementation-specific, a raw internal dump, temporary/high-cardinality, lacks a supported consumer, or has incomplete identity/provenance. Internal diagnostic access does not make it a stable public contract.
   - **Scientific evidence:** preserve in the separately governed durable/reproducible evidence plane. Operational observations may overlap in measured subject matter but are not substitutes for full-fidelity evidence or protocol artifacts.

   This policy is approved here; the concrete v1 field selection is not.

This is a code-confirmed semantic mismatch and likely under-reporting defect in the monitor; verify intended monitor semantics and add a focused regression test before changing it. It is outside the current source-tracing item and is not an implementation authorization.
